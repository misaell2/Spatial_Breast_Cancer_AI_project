# AWS EC2 + S3 Runbook

## Overview

This runbook documents how the `Spatial_Breast_Cancer_AI_project` workflow was executed on AWS using:

- **S3** for project input data, generated results, trained models, logs, and processed AnnData files
- **EC2** for cloud compute
- **Docker** for a reproducible analysis environment
- **IAM role-based access** for secure EC2-to-S3 communication

The goal of this milestone was to show that the spatial transcriptomics machine learning workflow can run outside of the local development machine in a cloud environment.

## AWS Resources Used

### S3 bucket

```text
spatial-bc-ai-misaell2
```

### EC2 instance

```text
Ubuntu Server 24.04 LTS
```

The EC2 instance was used to clone the GitHub repository, build the Docker image, pull input data from S3, run the full workflow, and sync generated outputs back to S3.

### IAM role

An IAM role was attached to the EC2 instance so the instance could access the project S3 bucket without storing AWS access keys on the instance.

The role allowed the EC2 instance to:

- list the project S3 bucket
- read input files from S3
- write generated outputs back to S3

### Security group

The EC2 security group allowed SSH access only from the user's IP address.

## Local Upload to S3

From the local project root:

```bash
export S3_BUCKET="spatial-bc-ai-misaell2"

aws s3 sync data/raw s3://$S3_BUCKET/data/raw
aws s3 sync data_manifest s3://$S3_BUCKET/data_manifest
```

Only raw input data and annotation manifests were uploaded before running EC2.

The following local folders were intentionally **not** uploaded before the EC2 run:

```text
data/processed/
results/
models/
```

Those outputs were generated by the EC2 workflow.

## EC2 Setup

After launching an Ubuntu EC2 instance and connecting over SSH:

```bash
sudo apt-get update
sudo apt-get install -y git curl unzip ca-certificates gnupg
```

AWS CLI was used to verify S3 access:

```bash
export S3_BUCKET="spatial-bc-ai-misaell2"

aws s3 ls s3://$S3_BUCKET
```

The EC2 instance accessed S3 through its attached IAM role, so `aws configure` was not used on EC2.

## Docker Installation on EC2

Docker was installed using Docker's Ubuntu apt repository.

After installation, the `ubuntu` user was added to the Docker group:

```bash
sudo usermod -aG docker $USER
newgrp docker
```

Docker was tested with:

```bash
docker --version
docker run --rm hello-world
```

## GitHub SSH Access from EC2

The repository was cloned using SSH.

An SSH key was created on EC2:

```bash
mkdir -p ~/.ssh
chmod 700 ~/.ssh

ssh-keygen -t ed25519 -C "ec2-spatial-bc-ai" -f ~/.ssh/id_ed25519_github

eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519_github

cat ~/.ssh/id_ed25519_github.pub
```

The public key was added to GitHub as a deploy key.

Then the repository was cloned:

```bash
mkdir -p ~/projects
cd ~/projects

git clone git@github.com:misaell2/Spatial_Breast_Cancer_AI_project.git
cd Spatial_Breast_Cancer_AI_project
```

From the EC2 project root:


Test the container:

```bash
docker run --rm spatial-bc-ai:aws
```

Expected output:

```text
Python 3.10.20
```

Test core Python packages:

```bash
docker run --rm \
  -v "$PWD":/workspace \
  -w /workspace \
  spatial-bc-ai:aws \
  python -c "import scanpy as sc; import sklearn; import pandas as pd; print('scanpy', sc.__version__); print('sklearn', sklearn.__version__)"
```

## Fix Output Directory Permissions

Because the Docker image runs as a non-root user, the mounted output folders needed write permissions:

```bash
mkdir -p data/processed results/figures results/tables models logs

chmod -R a+rwX data/processed results models logs
```

This allowed the container to write generated figures, tables, models, logs, and processed AnnData files to the mounted EC2 project directory.

## Run the Full Workflow on EC2

A timestamped run ID was created:

```bash
RUN_ID="ec2_run_$(date +%Y%m%d_%H%M%S)"
echo $RUN_ID
```

The full Dockerized workflow was run with log capture:

```bash
docker run --rm \
  -v "$PWD":/workspace \
  -w /workspace \
  spatial-bc-ai:aws \
  bash workflows/run_local_pipeline.sh 2>&1 | tee logs/${RUN_ID}_pipeline.log
```

## Cost Control

After the workflow completed, the EC2 instance should be stopped or terminated to avoid ongoing compute charges.

Recommended cleanup checklist:

```text
EC2:
- Stop or terminate the instance when finished.
- Check for unattached EBS volumes.
- Release unused Elastic IPs if any were created.

S3:
- Review stored data size.
- Keep only important run outputs.
- Delete accidental placeholder files if present.
```

One accidental placeholder file was observed in the model output prefix:

```text
s3://spatial-bc-ai-misaell2/models/ec2_run_20260602_170837/create
```

It can be removed with:

```bash
aws s3 rm s3://$S3_BUCKET/models/ec2_run_20260602_170837/create
```
